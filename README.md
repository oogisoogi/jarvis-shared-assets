# jarvis-shared-assets

로컬 AI 에이전트 운영 도구(cysr 터미널 기반)를 만들면서 나온 자산 가운데, 다른 프로젝트에서도 그대로 가져다 쓸 수 있는 것을 모아 두는 저장소입니다.
스터디 팀 규칙(「개발한 프로젝트에서 공유하면 좋을 기능·스킬·하네스를 별도 저장소로 추출해 공유 자산화한다」)을 따릅니다.

## 원칙

1. **복사해서 제자리 수정하지 않습니다.** 자산마다 판(태그)이 붙고, 쓰는 쪽은 판을 고정해 가져다 씁니다. 고칠 것이 있으면 이 저장소에 고치고 새 판을 냅니다.
2. **공개 전 검사 3종**을 통과한 것만 올립니다 — 내부 용어 0 · 개인정보 0 · 자격증명 0.
3. **원작자 몫은 분리**합니다. 원작 터미널(cys)에서 나온 코드는 원작 저장소의 라이선스와 표기를 따르며, 여기에는 우리가 새로 만든 스킬·훅·스크립트·문서만 둡니다.
4. 자산 하나 = 폴더 하나 + README(무엇 · 언제 쓰나 · 의존 · 판) + 자기 시험 1개 이상.

## 공개 전 검사

```bash
make check
```

- 들여온 파일의 해시 대조 → 검사기 자체 시험 → 자산 시험 → 공개 용어 검사 → 게이트 뮤턴트(금지 형태를 사본에 심으면 붉어지는가) → 이력 칸 검사(`origin/main` 뒤 커밋의 제목·본문·작성자·커미터).
- 공개 용어 목록은 둘로 나뉩니다. **구조 패턴**(개인 홈 경로 · 세션 주소 번호 · 전자우편 등)은 `tests/public-terms.txt` 에 공개돼 있고,
  **낱말 목록**(사람 이름 · 기기 이름 · 운영 은어)은 목록 자체가 공개되면 안 되므로 각자 루트에 `.public-terms-private.txt`(git 무시)로 둡니다.
  낱말 목록이 없는 기계에서 `make check` 를 돌리면 구조 패턴만 검사했다고 출력합니다 — 그 실행은 낱말 검사를 하지 않은 것입니다.
- 자격증명 검사는 이 저장소에 아직 없습니다(아래 「보류」 참조). 올리기 전에 각자 쓰는 비밀 검사 도구를 따로 돌려 주세요.

## 다음에 넣을 것 · 보류

- **발신 단일 입구 스크립트**(다른 세션에 글을 보낼 때 표식·원장·도달 판정을 한 번에 하는 래퍼) — **보류**. 원본이 특정 터미널의 화면 읽기·입력줄 판정·세션 기록 대조에 깊이 묶여 있어, 일반화가 아니라 재작성이 필요합니다. 환경과 무관한 부분(발신 원장 형식 · 표식 대조 규칙 · 정정 기록)만 새로 작성하는 안을 검토 중입니다.
- **시험 도구 모음** — 공개 용어 검사기만 들어왔습니다. 판번 일치 검사·비밀 검사는 원작 터미널 저장소에서 온 코드라 원칙 3에 따라 넣지 않습니다. 변이 시험 하네스는 프로젝트마다 따로 짜여 있어(시험 도구·대상 파일에 묶임) 공통 러너를 새로 써야 합니다.
- 그 뒤: 수신함 결정론 감시 · 자가 순환과 인계 서식 · 작업 지시서 서식(이월 · 되돌리기 어려운 결정 목록 · 위험 점검 4항) · 검증 거버넌스 문서.
